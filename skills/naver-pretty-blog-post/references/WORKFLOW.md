# 네이버 새 블로그 3곳 자동 발행 작업 지침 (예시)

※ 블로그 주소를 바꿨다면 옛 주소는 약 3개월간 새 주소로 연결된다. 크롬 프로필 폴더 이름은 처음 이름 그대로 둔다.
※ 발행 글 주소는 PostView 주소(새 주소 기준)로 ledger에 적는다.

대상: example_blog_1(재테크·절약·정부지원금), example_blog_2(건강·운동·식단), example_blog_3(쇼핑·제품 리뷰·가전)
각 블로그 하루 3편(09시, 13시, 19시). 사용자 보고는 쉬운 한국어로 짧게.

## 0. 먼저 지킬 것
- 사용자가 지정하지 않은 다른 블로그는 건드리지 않는다.
- 로그인·로그아웃·비밀번호 입력·계정 전환은 하지 않는다. 로그인이 풀려 있으면 그 회차는 `[blocked: 로그인]`으로 끝내고 사용자에게 알린다.
- 경험·후기·수치를 지어내지 않는다. 공식 자료를 직접 열어 읽은 내용만 쓴다. 건강 글은 "진단·치료를 대신하지 않는다"는 문구를 넣고, 재테크 글은 투자 권유와 수익 보장을 하지 않는다.
- 글은 합니다체. 본문 공백 제외 1,200~1,800자. 질문형 소제목 4개. 확인 날짜(오늘 날짜) 한 줄. 공식 링크 1개 이상 본문에 URL 그대로.
- 14일 안에 쓴 글과 같은 검색 의도는 쓰지 않는다 (ledger 확인).
- 이미지: 대표 1장(공개 이미지 또는 AI 생성 사진, 글자·얼굴 없음) + 3D 도식 2장(순서도/비교표/요약 카드/체크리스트 중 글마다 다르게). 숫자는 공식 자료로 확인한 것만.
- 실제 사용 후기처럼 쓰지 않는다. 제품 글은 "공식 시험·공식 자료를 정리한 글"이라고 밝힌다.

## 1. 준비 (매 회차 처음)
1. `Start-Process node <NAVER_ROOT>\toolkit\relay.cjs -WindowStyle Hidden` (이미 켜져 있으면 생략, 포트 9300)
2. 블로그별 제어용 크롬(포트 9231 dms, 9232 sh, 9233 tw)이 떠 있는지 `http://127.0.0.1:포트/json/version`으로 확인.
   없으면: `chrome.exe --user-data-dir="<NAVER_ROOT>\<프로필폴더>" --remote-debugging-port=<포트> --remote-allow-origins=* --no-first-run --new-window https://admin.blog.naver.com/<블로그ID>` 로 연다.
   프로필 폴더: 블로그마다 따로 만든 폴더 (예: 1_example, 2_example)
3. REPL에서 `eval(await fs.readFile('C:<NAVER_ROOT>\\toolkit\\naver-post-lib.js','utf8'))` 로 도우미를 불러온다.
4. `await isLoggedIn('<블로그ID>')` 가 false면 중단하고 사용자에게 로그인 요청 알림.

## 2. 주제 고르기
- `queue\<블로그ID>.json`에서 status가 '대기'인 첫 항목. 없으면 그 블로그 주제 안에서 새 질문형 주제를 직접 정한다(ledger와 겹치지 않게, 공식 자료가 있는 것만).
- 선택한 항목은 status를 '진행중' → 발행 후 '완료'로 바꾼다.

## 3. 조사와 글쓰기
- 공식 자료(정부24, 질병관리청, 한국소비자원, 공정위, 금융감독원, 제조사 공식 안내 등)를 WebSearch/WebFetch로 직접 읽는다.
- 글 표기법(txt): 빈 줄로 문단 구분, 한 문단 안의 줄바꿈은 줄 나눔(한 줄에 한 문장, 문장은 줄 안에서 끝낸다, 한 문단 2~3줄), `## 소제목`, `---` 구분선, `@img1`/`@img2` 도식 자리, `**강조색**`, `==형광펜==`, 마지막 문단 `#해시태그` 10개.
- 구조: 도입(이모지 + 독자 상황 2~3줄) → 확인 날짜 줄(📅 2026년 M월 D일 확인한 ... 기준입니다.) → `---` → `## 1️⃣ 질문형 소제목` ... → `## 4️⃣` 안에 `💡 **꿀팁포인트**` → 공식 링크 URL → 마무리 🌱 → 해시태그.
- 이모지를 문장 곳곳에, 핵심어에 형광펜. 도식은 소제목 2 또는 3 아래와 4 아래에 `@img1`, `@img2`.
- 글 흐름: SKILL.md의 「글 흐름 규칙」(한 줄 한 문장, 기승전결 소제목 순서)을 먼저 지키고, `node flow-check.cjs 글.txt` 로 줄 끝맺음·문단 길이를 확인한다.
- `await lintPost(txt, title, 건강글이면 true)` 로 검사. fails가 있으면 해당 부분만 고치고 다시 검사.

## 4. 이미지
- 대표: `await genHero('프롬프트(영어)', '파일명.png')` → 경로 반환. 제품 글은 브랜드 표시 없는 일반 제품, 얼굴 없음.
- 도식 카드: `await renderCard(블로그ID, NPC.blogs[블로그ID].bg[0 또는 1], '이모지 제목', 본문HTML, '출처: ... (날짜 확인)', 저장경로)`.
  본문HTML은 `cardRow('✅','내용 '+cardHl('핵심'))`, `cardArrow()`, `cardTable(['헤더'],[['칸']])` 로 만든다(행 4~5개 이내).
  배경을 새로 만들려면 `await genBg(블로그ID, '3D 소품 영어 나열', 'bg_새이름.png')` 후 그 파일명을 쓴다. 같은 배경을 연달아 쓰지 않는다.
- 만든 이미지는 반드시 열어 글자 깨짐·잘림을 확인한다.

## 5. 발행
```js
const B = NPC.blogs[블로그ID];
await buildPost(B.port, {blog:블로그ID, hero:대표경로, title:제목, txt:글, card:{1:도식1경로, 2:도식2경로}}, B.acc);
const url = await publish(B.port);          // PostView 주소가 나오면 성공
await ledgerAdd(블로그ID, {date, slot, title, url, topic});
```
- 발행 후 공개 주소를 열어 제목·이미지 3장·본문이 맞는지 확인한다. 실패하면 한 번만 같은 글을 다시 시도하고, 그래도 안 되면 `[blocked]`로 기록한다. 같은 글을 두 번 발행하지 않는다(ledger 확인).
- 카테고리는 기본 "게시판"에 올린다(사용자가 만들면 그때 지정).

## 6. 보고

## 7. 카테고리별 하루 1편 (2026-10-25 사용자 지정)
- 블로그마다 카테고리 3개(`categories.json`). 하루 3회차(09시, 13시, 19시)에 순서대로 카테고리 1, 2, 3에 한 편씩 쓴다. 09시=첫 번째, 13시=두 번째, 19시=세 번째.
- 주제는 `queue\\<블로그ID>.json`에서 그 카테고리의 '대기' 항목 중 첫 번째. 카테고리 항목이 없으면 그 카테고리 안에서 새 질문형 주제를 직접 정한다.
- 발행: `await publish(B.port, '카테고리이름')`. 카테고리가 선택되지 않으면 null이 돌아오므로 발행하지 말고 [blocked: 카테고리]로 기록한다.
- 오늘 같은 카테고리에 이미 글이 있으면(ledger의 date, category) 새로 쓰지 않는다. 놓친 회차를 보충 발행하지 않는다.
- ledger 기록에 category를 함께 적는다: `ledgerAdd(블로그ID,{date,slot,category,title,url})`.
